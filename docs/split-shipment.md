# 분할출고 잔여 계산 — 판단 과정

이 문서는 코드 설명이 아니라 **어떻게 판단했는지**의 기록입니다.
결론보다 그 사이에 틀린 것들이 더 볼 만하다고 생각해 남깁니다.

---

## 1. 발견

부분 출고에서 잔여를 이렇게 계산하고 있었습니다.

```
잔여 = 주문 − Σ 이전 차수에 걸어둔 수량(요청수량)
```

그런데 화면에는 다른 숫자를 보여주고 있었습니다.

```
화면 '실출고'   출고 이력에서 (취소분 제외)
잔여 계산       출고요청상세의 '요청수량' 에서
```

**두 숫자가 다른 표에서 나옵니다.** 평소엔 같지만, 어긋날 수 있습니다.

```
주문 1,000 · 1차에 400 걸고 확정 → 그중 100 취소

  걸어둔 수량   400   (취소해도 안 줄어듦)
  실제 나간 것   300

  화면          "1차 실출고 300"
  잔여 계산      1,000 − 400 = 600      ← 100개가 붕 뜬다
```

---

## 2. 첫 결론 — "일어날 수 없다" (틀렸다)

코드를 따라가 봤습니다.

```
출고확정 취소 → 그 차수의 출고 이력 전부 취소 표시
             → 출고요청 상태가 '확정' 이 아니게 됨
             → 분할 계산의 전제(이전 차수가 전부 확정)가 깨짐
             → 분할 모드 자체가 꺼짐
```

취소된 차수는 애초에 계산에 안 들어갑니다. 운영 데이터도 확인했습니다 —
차수가 있는 확정 건 6개 전부 `요청수량 = 실출고`, 어긋난 것 0건.

**"방어적으로 맞춰두는 것일 뿐, 지금은 못 일어난다"** 로 결론냈습니다.

---

## 3. 반증 — 되돌아오는 길이 있다

다른 담당(서버 PC)에 "이 판단을 깨보라" 고 넘겼습니다. 깨졌습니다.

```
1. 취소          상태 '확정' → '최종본확정'
2. 배정 축소      이제 가드가 풀린다. 400 → 300 으로 줄인다
                 ★ 요청수량은 아무도 안 줄인다
3. 문서 재생성     통과
4. 다시 확정      상태가 '확정' 으로 복귀 → 분할 모드 살아남
```

이 시점에 **요청수량은 400, 실출고는 300** 인 채로 분할 계산이 돌아갑니다.
제가 든 시나리오가 그대로 성립합니다.

결정적이었던 건 두 가지입니다.

- 이 사이클이 **화면의 버튼 하나**로 시작된다는 것
- 운영 출고 이력에 그 경로로 취소된 행이 **200행 넘게** 있고,
  `"수량 변경으로 재생성 필요"` 라는 사유까지 남아 있다는 것

실무에서 실제로 하는 일이었습니다.

---

## 4. 결론

```
지금 틀린 데이터가 있는가     아니오 (0건)
그렇게 될 경로가 있는가       예
그 경로를 실제로 쓰는가       예 (200행 이상)
```

**"못 일어난다" 가 아니라 "아직 안 일어났다"** 입니다.
방어적 수정이 아니라 시간 문제인 결함으로 다뤘습니다.

```python
# 전
잔여 = 주문 − Σ 출고요청상세.요청수량

# 후
잔여 = 주문 − Σ 출고이력.수량   (취소분 제외)
```

화면과 계산이 **같은 원천**을 봅니다.

---

## 5. 남은 생각

### 두 숫자가 다른 표에서 나오면 언젠가 어긋난다

지금 같은 것은 확정 흐름이 맞춰주고 있어서지, 그걸 강제하는 장치는 없었습니다.
"같은 값을 두 곳에서 계산하지 말 것" 은 흔한 말이지만, 이번처럼
**한쪽은 화면용, 한쪽은 판정용**으로 나뉘어 있으면 눈치채기 어렵습니다.

### 도달 가능성을 판단할 때 '직후' 만 보면 안 된다

저는 취소 **직후** 상태만 보고 닫았습니다. 상태 기계는 돌아옵니다.
"이 상태에서 저 상태로 갈 수 있는가" 가 아니라 **"돌아서 올 수 있는가"** 를
물었어야 했습니다.

### 반증을 남에게 시키면 값을 한다

스스로 반증하려 했지만 제 눈으로는 같은 데서 멈췄습니다.
"이 주장을 깨보라" 고 명시적으로 넘긴 게 효과가 있었습니다.

## 6. 회귀

이 판단을 코드로 고정했습니다. 그리고 **그 회귀가 진짜 잡는지** 확인했습니다.

```
[잡음] 잔여를 '걸어둔 수량' 으로 되돌린다 (옛 버그)
[잡음] 취소된 출고를 계산에 포함시킨다
[잡음] 취소된 차수를 계산에 포함시킨다
```

세 번째는 처음에 **놓쳤습니다.** 취소 차수를 출고 이력 없이 만들어놔서,
그 차수를 계산에 포함시켜도 결과가 안 변했습니다. 테스트가 아무것도
지키지 않고 있었던 것입니다. 돌연변이 하네스가 잡아줬습니다.
